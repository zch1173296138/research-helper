PaperQA 最值得学的是 Gather Evidence

PaperQA2 的优势不是单纯向量检索，而是先广召回，再把 chunk 转成面向问题的 scored summary， 最后只把高质量 evidence context 交给回答模型。

1

Broad Retrieval

先扩大候选池，保证召回。不要让 top-k 过早决定最终上下文。

2

Evidence Judge

逐条判断 chunk 是否能回答问题，输出 accept、maybe 或 reject。

3

Concise Summary

把原文片段压成可引用的证据摘要，并保留原始 chunk id。

4

Accepted Context

最终 prompt 只接收 accepted evidence，maybe 仅作为调试信息。

5

Citation Gate

答案只能引用 accepted ids，模型生成非法引用时回退或剔除。

当前：question -> hybrid retrieval -> raw chunks -> answer prompt
目标：question -> broad retrieval -> evidence decisions -> accepted summaries -> accepted-only answer

你的项目已经有不错的检索和会话基础，缺口集中在“检索结果如何变成可审计证据”。

你的项目已经有三块关键地基

这意味着不需要推倒重来。最小收益路径是在现有服务边界上增加 evidence layer。

Retrieval

HybridRetriever 已经够强

它已经组合了 LanceDB 向量检索、SQLite FTS/关键词检索、章节结构偏置、二次查询、 邻近 chunk 和 references 过滤。

Chat

PaperChatService 已有会话记忆

单论文聊天已经支持压缩记忆、最近消息窗口、追问 query rewrite 和 retrieval_metadata 持久化。

Storage

先用 JSON 存证据过程

ChatMessage.retrieval_metadata 已经是 JSON，第一版可以直接存候选、接受、拒绝和 judge_source。

建议按八步吸收 PaperQA 精华

顺序很重要：先提升回答质量和可审计性，再做外部 metadata、图片表格、多代理搜索。

Phase 1

单论文 chat 先接 evidence layer

新增 EvidenceRagService，包在 HybridRetriever 外面，不改检索器本身。

  • candidate_k = max(top_k * 3, 20)
  • 只返回 accepted evidence 给最终回答
Phase 2

定义 EvidenceDecision

每个候选 chunk 都有结构化判断结果，后续 UI 和调试都基于它。

  • decision: accept / maybe / reject
  • support_level、reason、concise_summary
Phase 3

先跑通无 LLM fallback

没有 API key 时，接受排名靠前的非 reference chunks，保持本地可用。

  • judge_source = fallback_ranked
  • 不破坏现有测试和本地体验
Phase 4

加入 LLM evidence judge

让 LLM 返回严格 JSON，并限制 chunk snippet 长度，控制成本和解析风险。

  • JSON parse failure 自动回退
  • 批量 judge，限制候选数量
Phase 5

accepted-only synthesis

最终 prompt 只看 accepted evidence summaries 和短原文片段。

  • 非法引用剔除或 fallback
  • missing evidence 更明确
Phase 6

把 evidence metadata 存起来

先不建新表，直接写入现有 retrieval_metadata JSON。

  • candidate_chunk_ids
  • accepted_chunk_ids / rejected_chunk_ids
  • final_context_chunk_ids
Phase 7

复用到 library chat

等单论文稳定后，让 /api/chat 也走同一套 EvidenceRagService。

  • 替换直接 VectorStore.search
  • 保留跨论文均衡检索策略
Phase 8

再做 enrichment

最后吸收 metadata、figure、table enrichment，并严格保留 provenance。

  • Crossref / arXiv / Semantic Scholar 可选
  • 生成描述不能冒充原文证据

优先级判断

目标是尽快得到可测量的回答质量提升，同时控制改动面和回归风险。

Do First

先做证据流水线闭环

EvidenceRagService、fallback judge、accepted-only synthesis、metadata 持久化。 这四件事是 PaperQA 精华在当前项目里的最小可用版本。

  • 单论文问答更稳
  • 引用更可审计
  • 失败时仍能本地 fallback
Do Later

暂缓 agent 和外部生态

不要第一步做 PaperQA agent、Crossref 全量接入、Docling 替换或复杂 evidence 表结构。 这些有价值，但会把核心收益延后。

  • agentic search 后置
  • metadata enrichment 后置
  • figure/table enrichment 后置
